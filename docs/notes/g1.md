## Integration fixes (all in the G1 commit)

### Wiring requested by the WPs

1. **`src/instrumentation.ts`** `[WIRE-INPROC-WORKER]` (wp2-to-integrator §1, wp0b-to-wp2 item 1).
   - It now calls `await import("./server/jobs/runner")` and then `startInprocWorker()`, wrapped in a try/catch that
     logs.
   - The worker is idempotent per process through WP2's `globalThis` guard.
2. **`scripts/lib/remote.ts`** (new) plus **`scripts/lib/limits.ts`** (wp2-to-integrator §2, wp0b-to-wp2 item 2).
   - `createRemoteLimitsAuthority(url, key)` wraps WP2's `RemoteLimitsAuthority` with the split-budget fallback
     (a laptop guard at 2 STT opens/min and 1 VA session).
   - `limits.ts` uses it by default and caches one client per URL and key. `registerRemoteAuthorityFactory` stays as
     a seam. `remote.ts` does not import `limits.ts`, so there is no ESM cycle.
   - `getLimitsAuthority()` now calls `loadEnv()` first. Before, a `LIMITS_AUTHORITY_URL` set only in `.env` was
     ignored: `aai-open` read the authority before it loaded `.env`, so it silently used the laptop guard.
   - Scripts need `tsx --conditions=react-server`, as every `npm run` script already has. `aai-open.ts` already
     required it through `va-node.ts`.
3. **`scripts/lib/aai-open.ts` token-auth open** (wp5b-to-integrator §1, for T-D1-3 part B).
   - The new option is `openVoiceAgentNode({ auth: { kind: "token", expiresInSeconds, connectDelayMs?, restBase? } })`.
   - It mints through `VoiceAgentRest.mintToken` (`max_session_duration_seconds` = the cap clamped to 60..10800) and
     then connects with `?token=` and no Authorization header.
   - The slot, ledger, heartbeat, report and release steps are unchanged. The default stays `{kind:"header"}`.
   - Two $0 tests in `tests/unit/platform/aai-open.test.ts` run against a fake token endpoint and a fake socket.
     The first checks that the header mode sends no token. The second checks that token mode mints once, puts
     `token=` in the URL, sends no header, and runs the full report/settle cycle.
4. **`src/server/limits/stt-params.ts`** `[WIRE-STT-PARAMS]` (wp2-to-integrator §3, wp4-to-wp2 §1).
   - `sttParamsFor` now returns WP4's `buildSttParams(call, policy, channel)`: TUNING_8K, Hinglish per channel, and the
     sanitizer.
   - It does this whenever both the call and the policy are known. The golden-defaults fallback remains only while no
     manifest entry exists (`[WIRE-CALLS]` waits for WP9).
   - The result is spread into the DTO, because the interface has no index signature.
5. **`src/server/jobs/runner.ts` `installBuiltinSteps()`** `[WIRE-WP8-STEPS]` (wp2 §5, wp8 §2).
   - It now imports `./verify-takeover` and `./va-audit`.
   - It then awaits `wp8HooksReady()`, so the ticker never runs with the step registered but the stale-VA handler or
     the audit hook still missing.
6. **`src/server/qa/wiring.ts`** `[WIRE-WP8]` (wp8-to-integrator §1).
   - The body is WP8's snippet verbatim.
   - The integrator added one thing: the three lazy hook imports are collected in a promise, exposed as
     `wp8HooksReady()`, and a registration failure is logged instead of becoming an unhandled rejection.
7. **`src/server/cases/defaults.ts`** (wp3-to-integrator §1).
   - WP1's engine (`impl:"wp1"`) and WP2's auth, rate limiter and ledger are bound. The code is WP3's snippet
     verbatim.
   - The "pre-G1 stub" warning no longer applies. `EXTRACTOR_VERSION_V3` is unchanged (`f03ba7a71306`), so the cache
     keys are the same.
8. **`next.config.mjs` `outputFileTracingIncludes`** (wp3-to-integrator §3).
   - `/api/cases` and `/api/extract` now trace `./data/cache/extract/**`.
   - It matches nothing until WP9 writes the cache.

### Breakages found at the merge

1. **The whole-project trace in `next build`.**
   - Cause: `src/server/limits/index.ts` (WP2) imports `scripts/lib/local-open-guard.ts`, and that file's
     `resolve(env || homedir…)` made Turbopack trace the whole repo into `.next/standalone`.
   - Fix: `/*turbopackIgnore: true*/` on the two `resolve()` calls in `local-open-guard.ts` (integrator-owned).
   - Result: 0 warnings, and 350 fewer files in the bundle.
   - One gitignored local file, `spikes/out/async-state.json` (4 KB), is still traced through the instrumentation
     chunk. It does not exist in the Zerops build container, so it does not matter there.
2. **`tests/unit/server/jobs/runner.test.ts` "stale VA slot … (default handler)"** (WP2).
   - Cause: `installBuiltinSteps()` now wires WP8, whose stale-VA handler takes precedence. That handler uses the
     global runner and DB, so it found no job in the test DB.
   - Fix: the test now drops WP8's handler (`registerStaleVaHandler(null)`) right after `installBuiltinSteps()`. It
     still pins WP2's default enqueue on its own runner, with the same assertions.
3. **Timing flakes under the merged, parallel suite** (61 files on one Postgres). Both fixes keep the assertions as
   they were.
   - **`extract-service.test.ts` "batches only a backlog"** (WP3). It failed in 2 of 3 runs on the plain merge,
     because DB timing decided which of 7 simultaneous calls went first. Fix: `rep-0` is started alone, the test waits
     until its luna call is in flight (held for 1 s), and then the other 6 are sent. Same expected batches: `[1,3,3]`,
     then `customer-0, rep-1, customer-1`, recent `rep-0`.
   - **`runner.test.ts` "the lease makes concurrent advances run the step once"** (WP2). The losing advances read
     `done` after the 50 ms step had finished. Fix: the step now sleeps 500 ms, so the three advances overlap.
