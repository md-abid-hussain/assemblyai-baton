### Decisions

1. **One tenant predicate, two schema generations.** `casesOrgFilter` probes `information_schema` once per
   process for `cases.org_id` and switches automatically when WP19's `0002_saas` lands. Before it, a `ws_<vid>`
   org scopes by `visitor_id`; after it, by `org_id` **or** `org_id IS NULL AND visitor_id = vid`, which is what
   keeps a pre-claim Baton run visible in its own device workspace (acceptance 2). A real `org_…` never falls
   back to the device, so a shared browser cannot leak one person's guest work into another's org (SAAS §2.6
   R1). A failed probe reads as "no `org_id`" — the safe direction.

2. **The checklist may not tick itself.** Each of the eight §8.3 items maps to one observed signal; an item
   whose owning WP has not shipped its signal reads *not done*, never done-by-default. Having edited a relay
   does not tick "Open the relay as code". The checklist is the judge path, so a friendly default would be the
   one dishonest surface on the page a judge walks end to end.

3. **The provenance strip under-claims.** `provenanceOf` returns WP7's persisted strip verbatim when
   `takeovers.metrics.provenance` exists, and otherwise derives what the row supports, reporting `aiHalf: none`
   rather than a hopeful `live`. Mistaking a simulation for a recording is the single error the strip exists to
   prevent, so wrong-in-the-cautious-direction is the only acceptable failure. Request filed with WP7.

4. **No blended number on `/app/analytics`.** Counts are per source and per outcome and are never multiplied
   into a "success rate". The "never blended" note states the absence rather than leaving it to be noticed.

5. **The org switcher is a seam, not a mock.** `setOrgDirectory()` lets WP19·3 supply the real list; until then
   the legacy principal genuinely owns one workspace, which is what the switcher shows. Rows are marked not
   switchable rather than silently doing nothing on click.

6. **The `/app` guard takes the path from its caller.** Next gives a layout no way to learn the pathname it
   wraps, and the `/start` redirect must return to `/app/runs?source=simulated`, not to `/app` (acceptance 1).
   The alternative was a header set in `src/proxy.ts`, which is WP12's file. Each page passes its own route
   literal; `tests/unit/app/wp20-surface.test.ts` fails if a new page forgets.

7. **`/start` continues on failure.** `POST /api/guest/start` does not exist until C3b, and after it a 429 is a
   *degrade*, not a block (§3.3 step 2). The device already carries a signed `bvid`, so the legacy workspace
   works either way. `safeNextPath` rejects `//host` and `/\host`; `<noscript>` has a real button, because this
   is the only wall in the product.

### What running it changed

Five defects, none of which the unit suite could have produced. The pattern is worth naming: **every one came
from a difference between what the code assumed about its environment and what the environment did.**

1. **`timestamptz` is a string from a raw `db.execute`** (above). The SSR tests passed because I wrote the
   fixture and the row type from the same wrong assumption.
2. **A defensive `.catch()` disguised it.** `/app/runs` caught the error and rendered "No runs yet." — telling a
   workspace with runs in it that it had none. It surfaced only on the detail page, which had no catch. The
   list is now reported as failed when it fails; the overview's degradations remain but each logs what it lost.
3. **`PaymentBadge` invented its vocabulary** (`paid`, `verified`). The real `PAYMENT_STATUSES` are
   `none|created|open|confirmed|succeeded|failed|expired|timeout`, so a genuine `succeeded` would have rendered
   neutral and under-reported a completed payment.
4. **An infinite redirect loop in orgs mode.** `POST /api/guest/start` answers
   `{ degraded: true, reason: "accounts_unavailable" }` when Better Auth is not configured for the deployment,
   and again on the §3.3 step 2 rate limit. `/app` then still had no org → `/start` → no org → `/app` → … A
   loop on the judged URL, caused by a degradation the spec explicitly calls non-blocking. `/start` now sets
   `cx_start_attempt` (no authority; a forged value only puts the visitor on the device workspace they already
   had) and the guard renders the read-only device workspace with §3.3's own sentence, "Continuing without a
   saved workspace — the demo works the same." Nothing reads like an outage.
5. **`err instanceof SaasError` was false.** Next loads the module graph more than once, so the error a route
   throws can be an instance of a different class object than the one the guard imported. Every anonymous
   `/app` visit 500'd instead of redirecting. The guard matches on the error **code** now;
   `tests/unit/app/guard.test.ts` throws from a second class to pin it.

A sixth, structural: **the layout must not redirect.** Next renders a layout and its page concurrently, so the
layout's redirect raced the page's and won with `/start?next=/app` instead of the page asked for. Pages own the
redirect; the surface test fails if the layout gains one.

### Decisions

- **Every auth form ends in `location.assign`, never `router.push`.** Signing in, signing up, accepting an
  invitation, creating an org and leaving one all change *which principal the server renders for*, and the
  client router cache still holds pages rendered for the previous one. A push repaints the shell over the old
  org's data. One document load on a page a person visits once is the cheap side of that trade.
- **The sub-nav is filtered on the server.** `visibleSettings(principal)` runs in the layout, so the browser is
  never handed the list of pages this role may not open. A hidden row is not a permission check and is not
  treated as one: every page re-checks, and WP19·3's routes re-check again.
- **`accountOnly` rows stay visible for a guest.** §8.5 is explicit that API keys and Webhooks must render the
  real surface behind the upgrade card rather than redirect, and those two pages are where a judge checks
  whether "real API, real SaaS" is a claim. Hiding the links would remove the check.
- **`?invite=<id>` carries the id, never the email.** The sign-up page reads the invitation server-side for the
  prefill. An address in a query string is written into history, into the referrer of every asset on the page
  and into any access log in front of the deployment — for a value the page can simply fetch.
- **The accept page says "you are signed in as someone else" *before* the button.** Better Auth refuses an
  accept whose session email differs, so without the check the page would offer a control whose only possible
  outcome is an error.
- **`MembersView.viewerRole` exists for one footnote.** §3.7 gives `member:manage` to owner *and* admin and
  then says "never an owner by an admin" in prose. Without the viewer's own role the page cannot encode that,
  and an admin gets a select and a 403.
- **The audit viewer is a server component with a plain GET form and no JavaScript.** Every state of the table
  is then a URL one admin can paste to another, Back steps through filters, and the screen whose job is to be
  *evidence* never depends on client state a reader cannot reproduce. Paging is keyset (`occurredAt|id`) and
  offers only "Older entries": the log gets new rows at the top while page 2 is being read, so an OFFSET would
  show one row twice and hide another.
- **Metadata is allow-listed on the way out.** §9 forbids secrets, key material, raw IPs and field values in
  `metadata`, and the writers respect it — but the viewer renders whatever is in the column, including rows a
  future WP writes. An allow-list of key *names* makes an upstream mistake an invisible row instead of a leak
  on a judged screen.
- **Sessions are rendered by id, and the token is fetched at the moment of the click.** Better Auth's
  `revokeSession` takes the session *token*, which is a live credential; putting tokens in a server-rendered
  row would ship every one of the user's session credentials into the HTML of a page.
- **No IP column on Profile**, though Better Auth stores one on every session row (§10.5). "Chrome on Windows ·
  started 24 Sep" is what a person actually recognises.
