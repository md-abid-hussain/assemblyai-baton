### Decisions

1. **`AuditAction` is a closed union of the §9 list, not `string & {}`.** §14 sketches the type as `string & {}`
   with the comment "exactly the §9 list"; the union *is* that list with the compiler checking it, and adding an
   action later is additive. The literal `string & {}` would accept any string, which is the opposite of a contract.
2. **`requirePrincipal` goes through the port.** `ports.ts` ⇄ `principal.ts` is a lazy ESM cycle (a hoisted function
   declaration, referenced only inside the getter), which is why `resolveLegacyPrincipal` is a `function` and not a
   `const`. The payoff: WP19·2 registers the session/API-key resolver and **no route file changes**.
3. **The same-origin check applies to `kind === "session"` only.** §3.9 says "our session-authenticated non-GET
   routes". Applying it to visitors would break v2: a cross-origin POST from a device is allowed today, and the
   test asserts it still is. API-key requests never read cookies and are exempt by the same rule.
4. **`isAnonymous` means an anonymous *account*** (the Better Auth anonymous plugin), not "no account at all". A
   visitor has `userId: null, isAnonymous: false`, and `account: true` refuses on `userId === null || isAnonymous`,
   so both are covered without overloading the flag.
5. **The default `Entitlements` is real, not a stub.** Limits come from `PLANS`; the plan comes from a swappable
   resolver (`ws_…` → guest, anything else → free) until WP21's `org_entitlements` exists; counts come from
   `setOrgCounter(key, fn)`, which owners register (`relays` → WP14b, `secrets` → WP16, …) and which reads 0 when
   unregistered, so no WP is blocked by another's absence; rates come from the registered `UsageMeter`. Simulated
   minutes do **not** draw on the monthly allowance (§4.5), only recorded and published ones do.
6. **`public-api.ts`: names frozen, fields deliberately thin.** The models WP22 owns the detail of (`RelayDetailV1`,
   `RunV1`, `CaseV1`, `UsageV1`, …) are `z.looseObject`, so WP22's richer real responses validate and every addition
   is additive. The shapes §6.2/§6.3 spell out in full (`ErrorV1`, `PageOf`, `MeV1`, `RelaySourceV1`,
   `CreateRelayV1`, `SaveSourceV1`, `SaveDraftV1`, `ValidateRequestV1`) are exact. Request bodies keep the spec's
   camelCase (`expectedRev`, `relayId`); wire payloads are snake_case.
7. **The default `RelaySourceStore` is read-only and empty** (`get` → `null`; `save`/`create` throw
   `E_UNPROCESSABLE`). §14 describes it as "serializes the canonical draft (read-only)", but the relay registry is
   WP14b's and is not in WP19's scope at C3, so serializing would mean importing across an ownership line. WP14b·4
   registers the real store; the behaviour difference is only "no source yet" versus "the draft's source".
8. **`src/server/env.ts` is untouched** (WP12's). `TENANCY_MODE` and `CONNECTOR_HOST_ALLOWLIST` are read from
   `process.env` directly with safe defaults (`legacy`, empty). If WP12 wants them in `EnvSchema`, that is a
   one-line request file; nothing here depends on it.
9. **`trustedOrigins`: passing the `appUrl` key overrides the environment**, including passing it as `undefined`,
   which is how a caller says "there is no APP_URL" without mutating `process.env`. Same for `errorDocsUrl`, which
   keeps the ordinary default-parameter behaviour instead.
10. **Additive helpers beyond the §14 listing** (all new names, nothing renamed): `assignableRoles`,
    `AUDIT_ACTIONS`, `AUDIT_SOURCE_SAVED_COALESCE_MS`, `EVENT_DATA_SCHEMAS`, `CodecCode`, `PAGE_LIMIT_DEFAULT/MAX`,
    `PUBLIC_API_VERSION`, `V3_ERROR_CODES`, `isV3ErrorCode`, `tenancyMode`, `requestIdOf`, `startPathFor`,
    `deviceOf`, `checkSameOrigin`, `setOrgCounter`, `setPlanResolver`, `resetSaasPorts` and the three
    `createMemory*` factories.
