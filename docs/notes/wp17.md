### Decisions

1. **TTS settlement: characters, calibrated live.** `usd = $0.0004 per request + $16 per 1M chars`. The smoke's SSE
   probe confirmed that `stream_format:"sse"`'s `speech.audio.done` carries `usage`
   (`{input_tokens:31, output_tokens:67}` for a 29-char line of 2.5 s: **26.8 audio tokens/s**, ≈ $0.019 per minute;
   the input tokens include the instructions). Clips run ≈ 1 s of edge padding + ≈ 45 ms per character, hence the
   per-request term. The formula sits slightly above usage (smoke: usage ≈ $0.0092, formula $0.0103). A 14-clip,
   1200-char sim ≈ $0.025 (PLATFORM §10.1). The binary pcm path stays (spec); switching to SSE and settling from
   `usage` is a drop-in change inside `speakPcm` if exact numbers ever matter.
2. **Customer voice instructions are constant**, so shared clips ("Yes, that's right.", …) hash to one `tts_cache` row
   across every relay and sample ("generated once, globally"). The sample colours only the rep's instructions.
3. **Each clip's edge silence is trimmed** (−50 dBFS, 30 ms pad) before placement, so the handoff times hug the speech.
4. **Handoff naming:** sims use the frozen v1 `CallHandoff` (`lineStartMs`, …, `declined:false`); PLATFORM's
   `repLineStartMs` = `lineStartMs`; `decisionPointMs = handoff.lineStartMs`.
5. **Over 90 s is an error, never a truncation** (truncating would cut the handoff). The script step shortens/regenerates.
6. **Ids:** `sim_<16 hex of sha256("sim/1"|kind|versionKey|sampleIndex|salt)>`. The id exists before the script (POST
   returns it at once, T3). The gallery build uses a fixed salt (deterministic ids); on-demand sims use a fresh salt,
   so a regenerated sim never reuses an id whose assets a browser cached as immutable. Insert is once-only.
7. **Raw SQL on 0001's tables** (`sim_calls`, `tts_cache`): the drizzle objects are in WP14b's `schema.ts`; raw SQL
   keeps WP17 independent of merge order. The DB tests create the two tables with `IF NOT EXISTS` copies of the DDL.
8. **`sim_calls.script`** stores `SimScriptStored` (normalized script + timeline + `relay {slug,title,blueprintHash}`);
   the row only has `relay_version_id`, and the manifest entry needs the slug and title.
9. **AI-half clips** are referenced by hash in `ai_clips` and served by the asset route as `clip.<sha256>.pcm` (only
   hashes the sim references). `purgeTtsCache` never deletes a clip a remaining sim references.
10. **Gallery manifest = a bundled JSON import** (no `outputFileTracingIncludes` needed). Gallery sims resolve with
    `relayVersionId: null` + `relay.slug`/`blueprintHash` (seeded version ids are random per database).
11. **Peaks** are computed from the decoded mu-law (what the client plays), same algorithm as WP9's `computePeaks`.
12. **Spend fails closed:** the server `TtsService` throws if the ledger is unavailable.

### Decisions

18. **The draft schema asks only for judgment.** Every mechanical field (normalizer, formatter, compare, capture,
    phrases, QA patterns, keyterms, tool lists, the second sample) is derived. A model cannot get them wrong if it is
    never asked, and two identical drafts then expand byte for byte.
19. **`expandDraft` repairs structure; the repair round is for judgment.** Stage order, tool lists, exits, consent,
    the money value behind a payment link and id uniqueness are mechanical - fixing them in code costs nothing, while
    a repair round costs a luna call and can fail. What code cannot invent (a business's enum values, for instance)
    is what the repair round is for. **Live result: 10 of 10 desks lint-error-free with zero repairs.**
20. **A drafted relay is created even when it still lints with errors.** §7.4 step 4 is explicit, and a relay whose
    errors are visible in the Studio is far more useful than a wizard that says "sorry".
21. **The job runs in this process until `JobKind` gains `"draft"`.** `DraftService.step(draftId)` already has the
    `{ state, next }` shape `JobRunner.register` takes; WP12 needs one enum value and one registration
    (`docs/notes/requests/wp17-to-wp12.md` §5). The **row**, not memory, carries the status, so a poll served by any
    container is correct meanwhile.
22. **Voiced sims are a Pro feature, by the plan table.** `voicedSimsPerDay` is 0 on Guest and Free and 2 on Pro
    (SAAS §4.1), so the refusal is a plan message pointing at the dry run and the pre-generated gallery call, not a
    bare 429. A plan refusal never spends a rate bucket.
23. **A sim id is stable for a (version, sample, day).** Asking twice in a day returns the same sim for $0; a sim
    regenerated on a later day gets a new id, so no browser can serve an asset it cached as immutable for a sim that
    no longer exists.
24. **The dry run makes its own extractor call.** Not to avoid `OpenAIExtractor` but because that class drops every
    event of a non-Baton relay (see [VERIFY] 4 below). Same prompt, same strict format, same effort and budget; the
    patch is parsed with a relay-aware schema and then filtered by `applyExtraction` against `spec.fieldIds`, which
    is the check that belongs there.
25. **`{subject}` left the default confirm phrase.** It renders "you" before a possessive ("you's owner phone")
    whenever the customer's name is not verified yet. `"the {label} is {f.X.display}"` is shorter and always reads.
26. **The drafted greeting's summary is one droppable clause.** Only a clause can be dropped (lint G2), and a long
    closing sentence - a spoken phone number, a long label - can push the render over 40 words. The opening, the
    opt-out and the next step are not negotiable; the summary is.
