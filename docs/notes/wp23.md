### Decisions

1. **`validateSource` takes the linter as an option, and `index.ts` wires it now.** TASKS-v3 expected a 5-line
   follow-up in WP23·2 because `lintBlueprint` was to arrive with WP14a at G2 — but WP14a·1/·3 are already on
   `main`, so `src/core/relay-code/index.ts` exports the wired `validateSource` today, and
   `codec.ts`'s `validateSourceWith(text, format, { lint })` stays kernel-free (and is tested that way).
   **Nothing is left for WP23·2 here.**
2. **Lint errors do not null the blueprint; everything else does.** `validateSource` returns
   `{ blueprint, hash }` set when only *lint* errors were found, because lint blocks Test and Publish, not Save
   (SAAS §5.2). Syntax, zod and `CODEC_CREDENTIAL` errors return `null`, so no caller can accidentally persist a
   file carrying a live key. `hasBlockingErrors()` is that predicate, exported for the save paths.
3. **Ranges follow the frozen contract: 1-based line, 0-based column.** `contracts/v3/relay-code.ts` says so;
   SAAS §5.3's `// 1-based` comment on the same type is the looser statement, and the frozen contract wins. The
   `yaml` `LineCounter` reports 1-based columns, so the codec subtracts one. Monaco wants 1-based columns, so the
   Code tab adds one back — spelled out with the snippet in `docs/notes/requests/wp23-to-wp15.md`.
4. **Explicit non-core YAML tags are refused.** `schema: "core"` + `customTags: []` still resolves an explicit
   `!!timestamp 2026-09-25` to a `Date` (found while writing the test, not assumed), which is exactly the type
   coercion SAAS §5.3 wants gone. The codec now walks the parsed document and refuses any explicit tag outside the
   seven core tags. Unknown tags were already a warning; they are promoted to errors.
5. **`CODEC_CREDENTIAL` also covers a `completion_webhook` URL**, not just `http_action`: the same secret in the
   same kind of place. Everything else is exactly the §5.2 list (`Bearer`, `Basic`, `sk_`, `cko_`, `whsec_`,
   `polar_oat_`, and 32+ base64/hex characters in a header named like `authorization`/`*key*`/`*token*`/`*secret*`).
6. **The generator drops zod's `"format": "starts_with"` marker.** No validator knows that name (ajv rejects it in
   strict mode) and the `pattern` beside it already carries the rule.
7. **`$defs.__schema0` is renamed `ValueRef`** so the published schema reads like the contracts.
8. **`serialize` orders keys by walking the zod shapes at runtime** rather than from a hand-kept key list: a new
   field in `blueprint.ts` appears in the right place with no edit here, and a removed one cannot leave a ghost.
9. **`npm install` was not used to add the dependencies.** It removed the worktree's `node_modules` junction and
   stripped every `libc` marker from `package-lock.json` (the same churn WP12 and G0 recorded). I reverted the
   lock, hand-wrote the two additive hunks (the root lists) and the one `node_modules/yaml` entry with the real
   integrity hash, restored the junction, and copied `yaml@2.9.1` into the shared `node_modules` so every worktree
   — including `main` — resolves it without an install. `npm ls yaml ajv` is clean.
