# WP11 → WP7 (call console): mounting the customer input

From WP11·1 (branch `wp/wp11`). Everything below is in **WP11's** paths (`src/client/customer/**`); the two changes
asked for are in **WP7's** (`src/client/session/wiring.ts`, `src/client/session/orchestrator.ts`). Nothing is
mounted today, so `/call` still behaves exactly as it does now until you make change 1.

## 0. What WP11 now provides

`createCustomerInput(deps)` from `@/client/customer` returns a `CustomerInput` (contracts/services.ts) plus two
extras (`CustomerInputExt`): `disableMic()` and `dispose()`. It implements DESIGN §5.15 in full:

- **suggestions** = WP14a's `suggestReplies` over the store, filtered to the phrases that actually have audio;
- **autopilot** = 600 ms after a request, a 4 s stall timer, one line during `pay`, off on the first chip / typed
  reply / mic, never over the agent, once per reply;
- **audio** = the committed pack `public/tts/manifest.json` (Baton takes, generated by `npm run tts:chips`) and a
  sim's `aiClips` by suggestion kind (PLATFORM §7.5 step 5, incl. each "Try an edit" preset's extra
  `answer:<field>` clip). Fed to `VoiceAgentControllerExt.playCustomerClip` at 24 kHz and played locally at 70%.
  **Zero live TTS**, ever: `/api/tts` is cut, so a phrase with no clip is dropped rather than faked.

## 1. Wire it in `createBrowserControllers` (please)

`SessionControllers.createCustomerInput?(c: SessionContext)` already exists and the orchestrator already calls it
(orchestrator.ts:382). It only needs the four things `SessionContext` does not carry:

```ts
// src/client/session/wiring.ts
import { createCustomerInput, type CustomerInputExt } from "../customer";

export function createBrowserControllers(o: BrowserWiringOptions & {
  store?: ConsoleStore;
  /** The sim's pre-voiced AI half when this run is a sim (`SimCallResolution.aiClips`); null on a Baton take. */
  aiClips?: Readonly<Record<string, SimAiClipRef>> | null;
  /** WP14a's compiled spec for a non-Baton relay (`compileRelay(bp).spec`); undefined on Baton. */
  spec?: () => IntentSpec | undefined;
} = {}): SessionControllers {
  let handle: TakeoverHandle | null = null;        // wireTakeover already builds one per page
  let customer: CustomerInputExt | null = null;
  return {
    // …unchanged…
    createTakeover: (c) => (handle = wireTakeover(c, o)),
    ...(o.store ? { createCustomerInput: (): CustomerInput => (customer ??= createCustomerInput({
      store: o.store!,
      va: () => handle?.va() ?? null,              // see 2 below
      engine: () => getAudioEngine(),
      setMicSource: (src) => handle?.setMicSource?.(src),   // survives a new pass, unlike the VA object
      ...(o.aiClips ? { aiClips: o.aiClips } : {}),
      ...(o.spec ? { spec: o.spec } : {}),
      offerTry: true,                               // Watch mode
      ...(o.log ? { log: (l, m, d) => o.log?.(l === "info" ? "info" : "warn", m, d) } : {}),
    })) } : {}),
  };
}
```

Two small things this needs from you:

1. **`TakeoverHandle.va()`** (or any getter for the current pass's `VoiceAgentControllerExt`). `wireTakeover`
   already holds `va` in its closure; WP11 only calls `playCustomerClip(pcm24k)` on it and tolerates `null`
   between passes. If you would rather not widen `TakeoverHandle`, pass `{ va: () => … }` into
   `createBrowserControllers` instead - WP11 does not care which.
2. **`CallSession.toggleMic(false)`** (orchestrator.ts, the `if (this.customer)` branch) currently returns `false`
   without stopping anything, so with a CustomerInput mounted the mic can be turned on but never off. Please call
   `(this.customer as CustomerInputExt).disableMic?.()` there, and `dispose()` alongside the other teardown in
   `dispose()`. WP11's `disableMic()` stops the track, clears the mic source and puts the audio session back to
   `"playback"`.

## 2. Console env

- **`inputs.typed`: please set it `false` for the Baton console.** Typed-reply TTS is CUT (P§13 X5). WP11's
  `sendTyped` only speaks a typed phrase when the committed pack happens to carry it and otherwise logs and does
  nothing, which is not a control worth showing.
- `inputs.autopilot` and `inputs.mic` stay as they are.
- `suggestions()` returns **exactly** the `Suggestion` contract shape (`id`, `text`, `audioUrl`, `voice`, `kind`),
  so `ui.suggestions` in a recorded bundle stays clean. `SuggestionChip` needs no change: `audioUrl` is non-null
  for every chip WP11 emits, and `voice` is `"recorded"` only for a tail-pack clip (none yet).
- The provenance strip's `customerInput` (`top-bar.tsx:174`) reads `!env.inputs.autopilot ? "mic" : "synthetic"`.
  Once this is mounted, `(customer as CustomerInputExt).mode === "mic"` is the accurate source; `"synthetic"` is
  correct for every other mode today.

## 3. What WP11 reads from your store (so you know what not to break)

`phase` (the AI half is `ai-*` / `paying`), `mode` (`recorded_ai` drives nothing), `callEnded`, `context.policy`,
`context.callId`, `caseState` (incl. `version`), `ai` lines with `kind === "speech"` (the finished spoken replies -
this is how autopilot sees `reply.done`), `va.{speaking,thinking,checking}`, `stage`, `payment.status`,
`aiConfirmed`. All read-only, through `getState()` + `subscribe()`.
