## 2. Trace `data/relays/*.json` into the standalone bundle (`next.config.mjs`, yours)

The gallery seed reads `data/relays/*.json` and `*.presets.json` with `fs` at run time (`FsGallerySource`,
`process.cwd()/data/relays`). As with the extraction cache, `data/` is not traced, so please add:

```js
outputFileTracingIncludes: {
  // …existing entries…
  "/api/relays": ["./data/relays/*.json"],
  "/api/relays/[id]": ["./data/relays/*.json"],
  "/api/relays/[id]/compiled": ["./data/relays/*.json"],
  "/api/cases": ["./data/cache/extract/**", "./data/relays/*.json"],   // WP14b·2 resolves relay versions here
},
```

Without it the Zerops gallery is empty, but nothing breaks: the seed logs no error and lists nothing.

## 3. Optional: seed at boot

The seed already runs lazily, once per process, before the first relay request is answered. It is idempotent by
content hash and serialized by an advisory lock. To have the gallery ready before the first visitor, call it from
`src/instrumentation.ts` in the `nodejs` runtime:

```ts
const { getRelaysDeps } = await import("./server/relays");
void getRelaysDeps().ensureSeeded();   // never throws; logs and retries on the next request
```

## 4. Purge job (P§2.4 "Size guards"; yours, when convenient)

Three steps for the purge job: `sim_calls` non-gallery rows unused for 7 days, with the cap at 150 rows (WP17 defines
"unused"); `tts_cache` rows unused for 14 days, except gallery clips; and optionally hard-deleting `relays` rows that
have been soft-deleted (`deleted_at`) for more than 7 days, when no `cases.relay_version_id` points at their versions.
Archived relays (`status = 'archived'`) must stay, because runs point at them.

## 5. Quota buckets used by `/api/relays/**`

These use WP12's `enforceRates` and `DbRateLimiter`. The bucket names and numbers are in
`src/server/relays/quotas.ts` and `src/core/contracts/ext/wp14b-relays.ts`:

| Bucket | Limit |
|---|---|
| `relay:create` | 10 per visitor per day |
| `relay:create:ip` | 20 per ipKey per day |
| 5 live relays per workspace | a count, not a bucket |
| `relay:save` | 120 per visitor per hour |

Clone-from-gallery is exempt. The global cap never refuses a create: at 400 live relays an idle one is archived, and at
2000 any LRU one. If you centralize the limits config, move the numbers and keep the names.
