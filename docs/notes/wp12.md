### P-0 probe

- **What ran.**
  - `zcli vpn up` works. `ssh app` works only with `-o KexAlgorithms=curve25519-sha256`: OpenSSH 10.5's default `mlkem768x25519` KEX hangs against Zerops's `zerops-v3.1.0` sshd.
  - The container is Alpine, user `zerops`, and has no `tcpdump`. The deployed build is G0, and the app logs no request headers, so the headers the app receives cannot be read from the log.
  - I then tried to check which env vars are set (names only, e.g. `VISITOR_SECRET` set or unset) so I could test in-process. **The permission system denied that as a production read.** I did not work around the denial.
  - The VPN is down again.
- **What the fix rests on.** The Zerops L7 balancer docs (docs.zerops.io/references/networking/l7-balancer-config, "Forwarded headers"):
  - `X-Real-IP` is the client IP, "always set by the balancer itself, overwriting any values sent by the client";
  - `X-Forwarded-For` is the client IP "appended to any existing chain";
  - `Forwarded` and `Proxy` are stripped.
  - Vercel (the remote mirror) also sets `x-real-ip` itself.
- **Fix (`src/server/auth/client-ip.ts`, re-exported from `@/server/auth`).**
  - `clientHop(headers)` = `X-Real-IP`, else the **rightmost** `X-Forwarded-For` entry, else `"unknown"`.
  - The hop is grouped by **/24** (IPv4, including IPv4-mapped IPv6) or **/48** (IPv6). Unparseable values become `"unknown"`.
  - `ipKeyOf` = `hmac(VISITOR_SECRET, "ip:" + dayUTC + ":" + clientHop)`. The format is unchanged, and the raw IP is never stored.
  - `IPKEY_MODE` sets the source: `real-ip` (default), `xff-right` or `off`. `off` returns a fresh random key per request, so per-ipKey buckets never bind and only the per-visitor buckets and global caps apply (P9).
  - `firstHop` is kept as a deprecated alias.
- **The probe for the integrator (PII-free; ships in this branch).**
  - `GET /api/status` with the header `x-ipkey-probe: 1` logs `ipkey_probe` with address **classes** only: `xffEntries`, `xffLeft`, `xffRight`, `realIp`, `realIpEqualsXffRight`, `forwardedHeaderPresent`, `keyedOn`. No IP is logged.
  - After the G2 deploy:
    ```
    curl -s -H "x-ipkey-probe: 1" -H "X-Forwarded-For: 203.0.113.7" -H "X-Real-IP: 203.0.113.9" https://app-2b25-3000.prg1.zerops.app/api/status >/dev/null
    zcli service log -P KZNwFJZjSFAVRky0p94BQA -S vUDumVp2Sg25qXBRHKmyxA --format SHORT --limit 50 | grep ipkey_probe
    ```
  - **Expected:** `realIp:"public"`, `xffLeft:"testnet"`, `xffRight:"public"`, `realIpEqualsXffRight:true`, `forwardedHeaderPresent:false`, `keyedOn:"x-real-ip"`. With that result, nothing needs changing.
  - **If `realIp` is `"testnet"`** (the client's value survived): set `IPKEY_MODE=xff-right`.
  - **If `realIp` and `xffRight` are private or CGNAT** (an inner hop): set `IPKEY_MODE=off`.
  - Set `IPKEY_MODE` in the GUI as a plain env var, then restart the app. It is deliberately not in `zerops.yml`, because `zerops.yml` `envVariables` would override the GUI value.
