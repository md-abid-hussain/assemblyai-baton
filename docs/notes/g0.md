## Contract decisions (DESIGN amendments for the planner to fold in)

1. **Turn ids (§5.1.7, §5.1.10, §4.1 `TurnInput.turnId`).**

   | Turn | Id |
   |---|---|
   | first live session of a channel | `${ch}-${turn_order}` |
   | g-th later live session (reconnect, hot upgrade) | `${ch}-${turn_order}-r${g}` |
   | cached turn: Express prefill, cached replay, partially cached channel, and the extraction-cache keys | `${ch}-c${turn_order}` |
   | sweep cut turn | `${ch}-cut-${n}` |

   Cached ids use the cached session's `turn_order` (that session starts at call ms 0), so they are stable per call.
   The DB key stays `(caseId, turnId)`. **Why ids and not a `(caseId, source, turnId)` key:** the WP9 cache files, the
   Express prefill and the client replay all need the same key, and one string is simpler.
2. **Millisecond columns.** Every call-clock or measured `*_ms` value and `billed_seconds` is `double precision`.
   Configured caps (`cap_ms`, `va_session_cap_ms`) and counters stay int. Zod fields stay `z.number()`; producers
   never round. **Why:** a forgotten `Math.round` would otherwise be a runtime 22P02 in the hot path.
3. **`fact_events`:** `turn_end_ms double precision NOT NULL` (no default) and `confidence NOT NULL`. Policy and
   `tool_update` events use `"high"`.
4. **`FactEvent.turnEndMs` is always on the call clock.**

   | Event | `turnEndMs` |
   |---|---|
   | extractor (luna) | the turn's `endMs` |
   | `tool_update` | `cases.t_arm_ms` + (server now − `takeovers.armed_at`), computed by the tool route |
   | `verifier` | `VerifierResult.uptoRecvMs` |
   | `policy` | 0 |

   `Evidence` keeps the VA clock in the AI half.
5. **Verifier events.** `kind:"verifier"`, `party:"verifier"`, `extractor:"sol"`, `turnId:null`.
   - `valueNorm` = sol's value.
   - `confidence` comes from sol's support: `stated_and_confirmed` → high, `stated_once` → medium, `conflicting` → low.
   - `evidence` = the first cited turn, or null.
   - `deriveField`'s main loop never adopts them; only `verifierOnly()` / `verifierDisagrees()` read them.
6. **`out_of_range`** is both a field flag and a PENDING status reason (the §5.4.1 `effective_date` guard).
7. **Assets.** `CallManifestEntry.assets` holds site-root-relative, content-hashed URLs, e.g.
   `/calls/<callId>/rep.<hash8>.ulaw`. It is `null` when `publishAudio` is false. Route #3 copies it.
8. **Data files** (all in `contracts/eval.ts`):
   - `public/data/cached-turns/<callId>.json`: raw `pc_ctx` Turn messages per channel with `recvMs`, plus
     `transcribedAt`;
   - `data/cache/extract/<callId>/<version>.<variant>.json`: per cached turn id, the events without id/caseId/seq,
     plus `extractMs`, `extractorVersion` and optional `cutTurns`;
   - `data/cache/verify/<callId>.<variant>.json`;
   - `data/evals/iterations.json` entries;
   - the `summary.json` envelope. **WP9b adds the curve and ablation shapes in
     `src/core/contracts/ext/wp9b-summary.ts` before WP10 starts (D2 09:00).**
9. **STT grants.**
   - `SlotResult.granted.sessionIds: string[]` (length n; `[rep, customer]`).
   - `SttTokenGranted.sessionIds: {rep?, customer?}`.
   - `SttTokenRequest.channel` is required when n=1.
   - WP2 creates one `live_sessions` row per id at grant time.
10. **pagehide:** use `fetch(url, {method:"POST", keepalive:true, headers:{Authorization}})`, never `sendBeacon`
    (DESIGN §5.5.3, §5.5.4 rule 8 and §5.9.5 say "sendBeacon").
11. **Error codes** `E_BAD_REQUEST` (400, zod failure), `E_FORBIDDEN` (403, token for another case, visitor or
    scope) and `E_NOT_FOUND` (404).
12. **Extractor output has no `seq`** (`NewFactEvent`). `ExtractResponse.events` (after apply) still has it.
13. **Sweep ablation.**
    - `SweepPoint.ablation` is `none` or `verifier_off`.
    - Explorer file = `/data/explorer/<callId>/<version>.<variant>[.<ablation>].json` via `explorerDataPath()`.
    - The other ablations (`pc_noctx`, `mono_diar`, `pc_ctx_8k`) are variants.
14. **VA cap.** `vaAcquire.capMs` (and so `live_sessions.cap_ms` for VA) = `VA_SESSION_CAP_MAX_MS` + 180 s = 600 s.
    `takeovers.va_session_cap_ms` keeps the dynamic cap.
15. **Payment tool result is server-built.** `PaymentView.toolResult` carries it once the payment is terminal. The
    browser only builds `timeout`.
16. **Invalid tool args → HTTP 200** with `INVALID_ARGS_RESULTS[name]` (`reason:"invalid_args"`). Route #14 uses
    `safeParseToolArgs()`. `hand_back_to_rep` never rejects: a hand-back must always work.
17. **`va.tool`** stays `ToolName`-typed. An invented name becomes an `error` event with `E_VA_CONFIG`.
18. **ToolDispatcher.** Default policy is `immediate`. A result is dropped only when its *carrying* reply was
    interrupted. `ToolTrace.replyId` records that reply.
19. **`conversation.message`** is banned by the boundaries test (the method stays, `@deprecated`, as a record of the
    tested API).
20. **`TurnInputSchema` is refined.** For `.omit/.pick`, use `TurnInputBaseSchema` (zod 4 refuses those on refined
    objects). `SttTokenRequestSchema` is refined too (`.extend` works; `.omit` does not).

TASKS §2 needs the same text changes for `SlotResult` and `CaseRepository.load().status`. The rest of TASKS is
unaffected.
