## 4. The config probe (how to answer "are the secrets set?" without reading a value)

zcli v1.1.2 cannot read a service's env, and reading it over SSH was already refused at WP12·0. So the check is a
route instead:

```
GET https://app-2b25-3000.prg1.zerops.app/api/health?probe=config
→ { ok, db, version, config: { ok: bool, missing: [NAME…], missingOptional: [NAME…] } }
```

- `src/server/health/config-probe.ts` builds it from `missingEnv()`, which compares against `undefined`/`null` and
  returns **names only**. A blank or whitespace value counts as unset (`readRaw` trims and drops empty strings), which
  is what a half-filled Zerops secret field looks like. A test asserts no value can appear in the output.
- `REQUIRED_SECRET_NAMES` (the live Baton slice cannot run without these; deploy.md "Secrets" step 1):
  `ASSEMBLYAI_API_KEY`, `OPENAI_API_KEY`, `CASE_TOKEN_SECRET`, `VISITOR_SECRET`, `ADMIN_KEY`, `CRON_SECRET`,
  `AAI_WEBHOOK_SECRET`, `AGENT_TOOL_SECRET`, `LIMITS_AUTHORITY_KEY`.
- `OPTIONAL_SECRET_NAMES` (Polar step 3; without them payments stay in mock/Simulate mode, which is the G2 criterion):
  `POLAR_ACCESS_TOKEN`, `POLAR_WEBHOOK_SECRET`, `POLAR_PRODUCT_ID`.
- It is **opt-in** (`?probe=config`), so the default `/api/health` body and the Zerops readiness check are unchanged.
