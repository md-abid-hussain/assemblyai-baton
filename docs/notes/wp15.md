### Decisions

- **`h-full` on the tab-body pane is load-bearing.** The pane is `flex-1` of an `h-dvh` column, but it is a plain
  block until `xl:grid` applies, so below 1280 px it sized to its content and Monaco's `height="100%"` collapsed to
  ~5 px. It rendered as an empty Code tab with no error anywhere. Fixed in `9781675`; the browser check found it,
  no unit test could have.
- **The JSON Schema is registered under every id the document's `$schema` can resolve to**, not just one.
  `getSchemaForResource` honours a document's own `$schema` *first and returns* — `fileMatch: ["*"]` is only
  consulted when there is no `$schema` line at all. Our files all carry `"$schema": "/schemas/blueprint-2.0.json"`,
  and Monaco resolves that against the **model** uri (`inmemory://model/1`), giving
  `inmemory://model/schemas/blueprint-2.0.json` — unregistered, and unfetchable with `enableSchemaRequest: false`.
  The visible symptom was a warning squiggle; the invisible one was **no completion and no schema validation at all
  in JSON mode**, i.e. the single thing Monaco gives us over the textarea. `schemaRequest: "ignore"` now suppresses
  only genuine *resolution* failures; `schemaValidation` is left at its default.
- **The `$schema` in the file stays relative.** An absolute URL would fix the resolution too, but it would bake one
  deployment's origin into every saved blueprint. Registering aliases is the smaller change.
- **Nothing imports `monaco-editor`.** It is a type-only import; the runtime arrives through
  `@monaco-editor/loader` from `/vendor/monaco/vs`. That is what keeps acceptance 7 true.
- **A failed Monaco load is not a broken tab.** `loadMonaco` has its own 10 s timeout (a 404 on `loader.js` can
  resolve as a load event), and the Code tab falls back to the textarea with a note naming the path it tried.
- Save still goes through `PUT /api/relays/:id/draft`; `source-store.ts` takes `save` as a dependency, so WP14b·4's
  `/source` is a one-line swap in `client/studio/api.ts`.
- The Code tab's `format` is a view preference, not document state: a reload opens YAML, which is what the file is
  stored as.

### Decisions

- **`applyEdit` has no "insert at", so a stage toggle appends and bubbles.** Turning a kind on has to put it in
  call order, and the only two primitives are `setIn` and `deleteIn`. Rewriting `playbook.stages` wholesale would
  work and would discard the comments inside **every** stage; `insertEdits` appends and then swaps the new item
  down into place, so only the stages that actually shift lose theirs. It costs 2·(n−index)+1 writes with n ≤ 4.
  The bubble walks a *working copy* — the second swap must read the list as the first one left it, and reading the
  original array instead is an off-by-one that is invisible in YAML and obvious in a plain-array test.
- **A stage's exit is written as one object, never key by key.** `ExitSchema` is a discriminated union whose keys
  change with the kind, so a two-step write would leave a stale `disclosure:` beside a new `connector:` — and
  since autosave is gated on zod, the visible symptom would be "Unsaved: 1 error to fix" appearing by itself.
- **`applyFormEdits` (batched) exists for edits that are independent by construction** — a swap, a type change.
  Anything else stays a separate call, because `swapEdits` reads its items from the blueprint it is handed:
  batching a rename and a move of the *same* field from one snapshot writes the pre-rename value back. The test
  says so out loud rather than just avoiding it.
- **A text control commits on blur, not on keystroke.** Each commit re-serializes, re-parses and re-compiles;
  per-keystroke it would rewrite a 450-line file sixty times a second and move the caret under the typist.
- **The greeting counter reads the Preview compile, not the template.** `{clause.wrap}` is one word in the box and
  eight in the ear, and a droppable clause may not be spoken at all. A second, cheaper count would disagree with
  lint G2 — which is the number that actually blocks Publish.
- **`plan: null` means "no plan layer here", not "the cheapest plan"** (`capabilities.ts`). A `guest` default would
  silently take HTTP actions away from a deployment that has no billing at all. WP21's `EntitlementView.plan`
  replaces the `null`; `studio-config.ts` carries the seam and says so.
- **A section jumps by *path*, a diagnostic by *line*.** A diagnostic already has a range and re-deriving it could
  disagree with the marker the builder clicked; a section has no range, and a path is the only thing that survives
  the edit they are about to make. `resolveTarget` rejects the codec's root fallback — `locate` walks *up* the path
  until something has a range, which is right for a diagnostic and would otherwise scroll a stale link to line 1 as
  if it had found the section.
- **Monaco's reveal is React state, not a ref.** It arrives in `onMount`, one dynamic import *after* the tab decides
  to use Monaco, so a ref left the fragment's pending jump writing into something nobody read again. Found in the
  browser; no unit test would have caught it.
- **The forms never disappear on a syntax error.** The store keeps the last valid parse, the controls render from
  it, and only writing is switched off — with three different sentences for the three different reasons (this
  viewer cannot edit / the deployment is read-only / the text does not parse).
- The picker offers **the secret ids this blueprint already references**, plus a checked free-text entry. There is
  no browser-side "list my org's secrets", and inventing one would put the org's secret names on a page that does
  not need them.

### The one failure, and why it is not in these files

A comment typed in Code, autosaved, is **gone after a plain reload of the same route**. `PUT /api/relays/:id/draft`
stores the parsed **blueprint**, so `client/studio/api.ts#sourceOf` re-serializes the text on load and every comment
(and the author's key order) dies at that boundary. The `# yaml-language-server:` header looks like it survived only
because `sourceOf` re-generates it.

This is **acceptance 1's fourth clause** and it cannot pass from WP15's side. `applyEdit` preserves comments through
every edit the forms emit — proven in `configure.test.ts` over a mixed run against the real Dental file. Raised as
**`docs/notes/requests/wp15-to-wp14b.md`**, with the measurement and the two-line honest fallback if `/source`
