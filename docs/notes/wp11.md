## WP11·1 — autopilot + suggestion chips + the mic toggle (D2 17:00)

### Done

**`src/client/customer/**` — the `CustomerInput` the /call orchestrator has been waiting for.** The seam
(`SessionControllers.createCustomerInput`, orchestrator.ts:382) already existed and was never filled; it is now.
Four modules:

| file | what it is |
|---|---|
| `manifest.ts` | the committed chip pack's shape (`public/tts/manifest.json`), the clip URL, and the one text-normalizer the generator and the page share |
| `clips.ts` | the two clip sources — the committed pack (text-keyed, per take) and a sim's `aiClips` (kind-keyed) — a first-hit-wins chain, and a caching PCM loader |
| `autopilot.ts` | **pure**: `planAutopilot(snapshot)` → when to speak and why (`reply` / `stall` / `pay`) |
| `suggestions.ts` | WP14a's `suggestReplies` bound to the audio that exists; drops phrases nothing can voice |
| `customer-input.ts` | the controller: store subscription, one timer, chips, typed, mic, `dispose()` |

**Autopilot** is DESIGN §5.15 exactly: the top suggestion 600 ms after a reply that ends in a request; a 4 s stall
timer otherwise (preferring "Sorry, could you repeat that?" over an unvoiced "Okay."); one line during `pay` and
never the card; never over the agent (`va.speaking || thinking || checking`); once per reply; off the instant the
judge uses a chip, the text box or the mic. The loop breaker is not re-implemented here — `suggestReplies` already
produces the explicit field-plus-value sentence from the reply history, and the pack voices it.

**Chips** come from `suggestReplies` and are then bound to audio. On a Baton take that is a text lookup in the
committed pack. On a sim it is `aiClips` by suggestion kind, and **the clip's own text wins**: a chip reads exactly
what the judge is about to hear. A sim's scenario truth never reaches the page, so `suggestReplies` alone would
answer "I'm not sure, sorry."; `buildSuggestions` replaces that with the pre-voiced `answer:<field>` clip for the
classified field. That is also why **"Try an edit" presets cost nothing**: WP17 already voiced each preset's extra
field, and the same lookup finds it.

**Mic**: `enableMic()` → `engine.openMic(24000)` → WP7's `TakeoverHandle.setMicSource` (which survives a new pass),
audio session `play-and-record`; `disableMic()` puts it all back. A blocked mic returns `false` and leaves autopilot
and the chips working (the orchestrator raises `E_MIC_DENIED`). This is both the Baton option and the sim's
"Answer the AI yourself (mic)" toggle of PLATFORM §7.5 / §7.1.

**`scripts/tts/generate-chips.ts` + `public/tts/` — the committed clip pack (44 phrases).** `/api/tts` is cut, so
every phrase the s01 autopilot or a chip can say is generated once and committed: `npm run tts:chips` prints the
plan and the cost and writes nothing; `RUN_LIVE=1 npm run tts:chips` generates. Voice `marin` with WP17's
`CUSTOMER_INSTRUCTIONS`, model pinned, hashed `sha256(model|voice|instructions|text)` — the same key the sim TTS
cache uses, so a phrase shared with a sim is the same clip. **The cache defaults to the output directory**, so the
committed clips *are* the cache: regenerating the manifest for a newly recorded take of the same scenario is $0.

### Decisions

1. **The page cannot know the scenario truth** (`Scenario.truth` is not in `CreateCaseResponse` and I do not own
   that contract), and `suggestReplies` needs it. The chip pack carries the take's truth alongside its clips — one
   fetch, one source, and a take the pack was not generated for resolves **nothing** (another take's truth is not
   this take's truth; a wrong-scenario phrase must never be spoken).
2. **Nothing is ever synthesized at run time.** A phrase with no clip is dropped from the chip list, and autopilot
   simply has nothing to say for that reply rather than pretending (DESIGN §7.5). If the pack resolved *nothing at
   all* the texts are still shown, so the judge can read what the customer would say.
3. **Typed TTS stays cut** (P§13 X5). `sendTyped` speaks only if the pack happens to carry that exact phrase.
   WP7 is asked to set `inputs.typed = false`.
4. **The store, not the event stream, is the input.** Every fact autopilot needs is already reduced in WP7's store
   (finished spoken replies, stage, payment, case snapshot, policy), a recorded bundle replays through the same
   store, and `suggestions()` had to read it anyway. `reply.done` is seen as "an `ai` line's `kind` became
   `speech`".
5. **`suggestions()` returns the bare `Suggestion` contract shape.** The internal `clip`/`field` stay internal so a
   recorded bundle's `ui.suggestions` entry does not grow private fields; `audioUrl` is enough to replay a chip the
   UI hands back.
6. **Autopilot marks a reply as handled before it tries to speak.** A missing clip, a 404 or a closed VA session
   otherwise re-armed a 0 ms timer forever. Found by a test that hung; the test clock now fails on a timer loop.
7. **`buildIntentSpec`/`compileRelay` is the seam for non-Baton relays**, injected as `spec?: () => IntentSpec`.
   Without it the Baton lexicon is used, which is right for Baton and wrong for Dental — the Dental tests compile
   the shipped `data/relays/dental-deposit.json` and pass its spec, which is what the Studio console will do.

### Integrator actions

1. **Mount it.** `docs/notes/requests/wp11-to-wp7.md` asks WP7 for two small changes: a getter for the current
   pass's Voice Agent controller, and `toggleMic(false)` / `dispose()` calling WP11's `disableMic()` / `dispose()`
   (today `toggleMic(false)` is a no-op once a `CustomerInput` is mounted, so the mic could not be turned off).
   Until that lands, `/call` is unchanged — nothing here is wired in.
2. **`scripts/ci/staged-key-scan.mjs` does not treat `.pcm` as binary.** It scanned all 5.6 MB of
   `public/tts/*.pcm` as latin1 text against ten credential patterns. It passed, and WP17's committed sim clips
   pass too, but this is a false-positive waiting to happen on the next voiced clip and it slows every commit.
   Please add `pcm|ulaw|raw` to that script's `BINARY` regex (WP12's path, so I have not touched it).
3. **`BATON_DEPLOY_ID`'s value is a plain deploy label** (`dev-…`), not a secret, but the hook blocks any `.env`
   value of 8+ characters, so `scripts/tts/generate-chips.ts` builds its ledger env label at runtime
   (`["dev", "wp11"].join("-")`). Worth knowing before the next script hits it.
4. **`public/tts/` carries 44 `<hash>.json` sidecars** (~5 kB total) next to the clips: they are the TTS cache's
   metadata, and keeping them is what makes a regeneration $0. They are served publicly and contain only model,
   voice, text and duration.
5. Deploy size: `public/tts` is **5.6 MB** (44 clips × ~2.5 s of 24 kHz PCM16). For comparison `public/calls` is
   7.7 MB. Within TASKS-v3 §8's deploy note, but it is real.
